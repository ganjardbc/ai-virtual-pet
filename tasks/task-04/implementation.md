## Implemented

- Drizzle schema (`apps/api/src/db/schema.ts`) for the three tables:
  - `pets`: text primary key; `name`, `species` (default `DEFAULT`), `stage`, `created_at`, `hatched_at`, `updated_at`, `version`.
    - Checks: stage values (`EGG`, `BABY`); Egg ⇔ no `hatched_at` and no name; non-Egg ⇒ `hatched_at` set; name length 1–30; version ≥ 0.
  - `pet_states`: one-to-one with `pets` (`pet_id` is both primary key and foreign key, cascade delete).
    - Stats are `double precision`, each checked to 0–100.
    - `current_activity` is checked against the allowed values, and `sleep_started_at` must be set exactly when the activity is SLEEPING.
  - `events`: append-only.
    - Identity `bigint` primary key, `pet_id` foreign key (cascade), `type`, `occurred_at`, `data` jsonb, `schema_version`, `created_at`.
    - Indexes on `(pet_id, occurred_at)` and `(pet_id, type, occurred_at)`.
  - All timestamps are `timestamptz`.
- Migration `apps/api/drizzle/0000_initial_pet_persistence.sql`, generated by drizzle-kit and applied to `ai_virtual_pet`.
- `db/client.ts` (`createDatabase`), `db/migrate.ts` (`runMigrations`, works from both `src` and `dist`), and `config/env.ts` (shared root `.env` loading). `db/check.ts` now uses the shared env loader.
- `package.json` scripts `db:generate` and `db:migrate`, plus a workspace dependency on `@ai-virtual-pet/domain`.
- Repository contracts (`persistence/repositories.ts`):
  - `PetRepository`: `findCurrent`, `findById`, `create`, `save`, `deleteAll`.
  - `EventRepository`: `listRecent`, `listOccurrenceTimes`.
  - Types: `PetAggregate`, `StoredEvent`.
  - Errors: `ConcurrencyError`, `PetNotFoundError`.
- `DrizzlePetRepository` and `DrizzleEventRepository` (`persistence/drizzle.ts`):
  - Row ↔ domain mapping stays inside this file.
  - Loaded states are re-validated through `createPetState`, and loaded pets are rebuilt as `EggPet`/`BabyPet`.
  - `create` writes pet, state, and initial events in one transaction.
  - `save` updates pet and state and appends events in one transaction guarded by `WHERE version = expected`. It returns `ConcurrencyError` or `PetNotFoundError`.
- `InMemoryStore` (`persistence/memory.ts`) implements both contracts with deep-copy isolation, for fast Phase 4 application and API tests.
- Shared contract tests (`persistence/repositories.test.ts`) run against both implementations, plus PostgreSQL-only tests:
  - Reload through a new connection.
  - Transaction rollback.
  - Seven database constraint checks.
- Test helper `testing/database.ts` (excluded from the build): opens the test database, runs migrations, truncates tables, and refuses to run if `TEST_DATABASE_URL` equals `DATABASE_URL`.
- Created the local database `ai_virtual_pet_test`. Added `TEST_DATABASE_URL` to `.env.example` and to the local `.env`.
- README: added a Local Development section with setup steps and the migration workflow.

## Decisions and Deviations

- **No `users`, `pet_personalities`, or `pet_growth` tables**, even though data model §125 lists them for the minimal schema. Prototype 0.1 has no authentication, personality, or growth (scope §48, §73–74, §78), and empty tables would be behavior-free scaffolding. `species` and `version` are kept because they are cheap and follow the documented model.
- **The Egg has a `pet_states` row from creation** (data model §108), so the aggregate always has a state. Phase 4 should not simulate an Egg and should reset `lastSimulatedAt` at hatch.
- **Event ids are identity integers, not UUIDs**, which gives a stable order when timestamps tie. `interaction_id` and `source` columns are deferred until something writes them. Simulation events already carry `source` in `data`.
- **`save` combines the state write and the event append** in one call, so they can never commit separately. `EventRepository` is read-only.
- **The stage check allows only `EGG`/`BABY`**, matching the domain. Adding `CHILD`/`ADULT` later is a one-line migration.
- **Development source resolution:** the API resolves `@ai-virtual-pet/domain` from source for typecheck (tsconfig `paths`) and Vitest (alias), as in Task 03. The build uses the compiled package. `rootDir` moved from `tsconfig.json` into `tsconfig.build.json` to allow this.
- **Vitest runs API test files sequentially** (`fileParallelism: false`) because database suites share one test database.
- **Integration tests are skipped when `TEST_DATABASE_URL` is empty**, so a machine without PostgreSQL can still run `pnpm test`. The in-memory contract tests still run.

## Known Limitations

- `pnpm dev` for the API loads workspace packages from `dist`, so run `pnpm build` first (now documented in the README).
- `findCurrent` returns the latest pet. Enforcing a single pet is left to the Phase 4 application layer (`POST /pet` when one exists).
- There is no retry policy for `ConcurrencyError` yet. Phase 4 decides whether to retry or return 409.
- Nothing persists the previous mood (needed for mood stability) yet. See the Task 03 limitations.
